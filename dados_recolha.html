3  Recolha de dados

A recolha de dados combina processos automáticos (carregamento de feeds GTFS, extração OSM e recolha de GTFS-RT) com fontes externas fornecidas pelos operadores. O processo é controlado pelo ficheiro de parâmetros prioritise_parameters.R, que define, para cada região de análise, os URLs das fontes de dados, os parâmetros de filtragem e as configurações específicas.

3.1 GTFS

O feed GTFS é transferido diretamente do URL oficial do operador no início de cada execução da análise, garantindo que a versão mais recente da oferta programada é utilizada. O carregamento é realizado com a função GTFShift::load_feed():

gtfs <- GTFShift::load_feed(region$gtfs_url,
          headers = if (!is.null(region$gtfs_url_headers))
                      unlist(region$gtfs_url_headers[[1]])
                    else NULL)

Após o carregamento, o feed é filtrado para o dia de análise definido (gtfs_day), usando tidytransit::filter_feed_by_date(). Este passo garante que apenas os serviços operacionais nesse dia específico são considerados. O feed filtrado é guardado localmente em formato .zip para referência futura e reprodutibilidade.

Quando necessário, é aplicada uma função de manipulação customizada ao feed (gtfs_manipulate), que permite corrigir eventuais inconsistências nos dados de origem antes de prosseguir com a análise.

3.2 OpenStreetMap

A recolha de dados OSM é realizada a partir de um ficheiro local no formato .pbf (Protocol Buffers), obtido do serviço Geofabrik. A utilização de um ficheiro local, em vez da API Overpass, permite processar grandes áreas geográficas sem limitações de taxa de pedidos.

O ficheiro .pbf é descarregado com osmextract::oe_download() e é identificado com a data do dia de execução no nome, garantindo que é utilizada a versão mais recente disponível:

osm_file <- osmextract::oe_download(
  sprintf("https://download.geofabrik.de/%s-latest.osm.pbf",
          region$geofabrik_region),
  file_basename = sprintf("%s_%s.osm.pbf",
                          region$geofabrik_region,
                          format(Sys.Date(), "%Y%m%d"))
)

A consulta OSM é construída com a biblioteca osmdata, especificando os atributos de rota relevantes para a região (e.g., route = bus, network = Carris). Esta consulta é parametrizada no ficheiro de configuração e pode ser adaptada a diferentes operadores e modos de transporte.

3.3 GTFS-RT

A recolha de dados GTFS-RT é um processo contínuo, realizado de forma independente antes da execução da análise principal. Os dados são recolhidos em intervalos regulares (definidos pelo parâmetro rt_interval) ao longo de um período de observação, e guardados em ficheiros CSV individuais. Cada linha de um ficheiro CSV corresponde a uma atualização de posição de um veículo (VehiclePosition), contendo, no mínimo:

Campo Descrição
trip_id Identificador da viagem GTFS
route_id Identificador da linha GTFS
vehicle.position.latitude Latitude do veículo
vehicle.position.longitude Longitude do veículo
vehicle.timestamp Marca temporal da atualização
speed Velocidade reportada pelo veículo (quando disponível)

No início da análise principal, todos os ficheiros CSV recolhidos são carregados e combinados num único data frame (rt_collection_raw). Quando necessário, é aplicada uma função de manipulação customizada (rt_collection_manipulate) para filtrar ou transformar os dados antes do processamento, por exemplo, para excluir atualizações fora do período de análise ou com qualidade insuficiente.

3.4 Dados de procura

Os dados de procura são fornecidos pelos operadores em formato CSV, com pelo menos duas colunas: route_short_name (nome curto da linha) e demand (procura diária de passageiros). O ficheiro é lido no início da análise e os valores são associados às linhas GTFS correspondentes através do route_id.
